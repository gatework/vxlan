# ctx_cli Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Preserve existing uncommitted changes; no commits or publication are authorized.

**Goal:** Extract shared CLI responsibilities into ctx_cli and migrate existing consumers without adding a baseline command.

**Architecture:** Small Ruby objects composed by domain adapters. ctx_cli has no dependency on net-connector or ctx_runner; existing connector configuration policies and Runner business processes remain their owners' responsibilities.

**Tech Stack:** Ruby >= 3.4, OptionParser, YAML, dotenv, RSpec, RuboCop Omakase. Development Ruby 4.0.6.

**Spec:** ../specs/2026-10-22-ctx-cli-design.md

## Global Constraints

- Preserve current CLI contracts, configuration discovery, precedence and source-relative paths.
- No new baseline executable; coverage.rb is the existing script integration.
- No automatic network I/O, ENV mutation, input consumption or directory creation on require.
- Preserve vendor parser names/layout, unrelated WIP, and existing ctx_runner/Inventory work.
- Chinese code comments, English RSpec/Changelog, explicit require and package allowlist.
- Keep net-connector Ruby >= 3.4; no dependency cycle or implicit sibling checkout loading.

## Review Focus

- Reused CLI objects must start a fresh batch and leave previous reports intact after preflight failure.
- Output or directory-sync failure after an external effect must not turn into success or replay.
- Missing/false/nil and overridden invalid values must retain existing configuration semantics.
- Non-TTY input and caller-owned IO must not be consumed/closed by help or preview.
- Installed packages must exercise actual candidate dependencies rather than workspace load paths.
