# 证据契约驱动的优化设计

目标：验证原始输入、领域事实、完整性状态及批次报告之间的可信关系，再集中重复规则。范围沿用用户已批准的三个切面：解析可信性、失败可信性、规则唯一性。

约束：保留现有 WIP、公开入口和独立 gem 边界；Ruby >= 4.0.6；不提交、不发布、不连接设备；不复制凭据或未经脱敏的私有回显进入仓库。当前目录已有用户要求的连续改动，继续原位实施；临时快照隔离差分和变异运行，不新建分支、不清理工作树。

证据：区分历史来源未核实、人工合成、官方资料派生、历史设备保存回显。每个新样本记录命令、平台、来源、转换说明和 SHA-256，预期值直接人工标注，不使用生产辅助方法推导。官方样例不是实机兼容验收；样本不足保持明确未验证。

不变量：等价身份不绕过冲突检查；作用域不能串扰；缺少必需证据不能 complete；任一失败不擦除已获取事实；摘要失败不能留下假成功；声明的配置允许值和实际消费保持一致。减少重复知识，不追求减少厂商语法本身。

交付：契约矩阵、最小实现改动、独立字面量预期、变形/故障/定向变异证据、差分回放及隔离安装记录。没有解释的行为差异不能通过验收。
